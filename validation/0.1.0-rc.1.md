## Live hardware evidence

One live host was available during implementation and was exercised with the
release binary (not a substitute):

- Host: Linux 7.1.8-1-cachyos, in-tree `amdgpu`, AMD Radeon AI PRO R9700
  (Navi 48 / RDNA4, PCI `1002:7551`), discrete 32 GiB VRAM, `gpu_metrics`
  v1.3, no ROCm userspace requirement exercised; run as an ordinary user.
- Discovery and topology matched the host (one physical GPU, one partition).
- Cross-checks against kernel files: activity == `gpu_busy_percent`;
  memory == `mem_info_vram_used/_total`; hotspot == hwmon junction
  (`temp2_input`/1000); power cap == `power1_cap`/1e6; hotspot limit ==
  `temp2_crit`/1000.
- The SMU's intermittent idle throttle report (`throttle_status=0x2`,
  `indep_throttle_status` bit 36) surfaces as the factual sentence
  `thermal throttle active`; when the bits clear, health returns to
  `no active limits or faults`.
- Startup → first output over 20 release-binary samples after review repairs:
  min 393 ms, median 396 ms, max 397 ms (budget: ≤ 1 s).
- 30 s `--json-stream` run after review repairs: 123 records, zero
  sequence gaps, tick deltas min/p50/p95/max =
  250.0/250.2/250.2/250.4 ms, and zero deltas ≥ 500 ms.
  No production tick was missed.
- TUI ran live and matched the approved visual composition; quit restored
  the terminal.

This run used live fixtures of opportunity, not a formal lab pass. The
workload-perturbation budget (≤ 2 % regression on a representative stable
GPU workload) was **not measured**: no repeatable representative workload
harness exists on this host. That measurement is the remaining external
prerequisite for claiming the discrete-RDNA regime fully qualified.
