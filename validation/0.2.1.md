## Changes since 0.2.0

- Fix a permanent false `thermal throttle active` on discrete RDNA 3/RDNA 4
  GPUs. Their firmware keeps `TEMP_HOTSPOT` (`indep_throttle_status` bit 36)
  set even at idle (drm/amd#3251, ROCm/rocm-systems#11781). GPUFlo ignores
  that bit in `gpu_metrics` v1.3, matching MangoHud, and decides throttling
  from `indep_throttle_status` whenever the kernel supplies it.
- Add `theme = "terminal"` / `--theme terminal` (#31).
- Document Omarchy 4 (Quattro) launch, menu, and status-bar setup, and add the
  repository-only `scripts/omarchy-bar` wrapper (#30).

## Live hardware evidence

- Release qualification host: Linux 7.2.5-3-omarchy, in-tree `amdgpu`, two
  discrete GPUs: AMD Radeon AI PRO R9700 (Navi 48 / RDNA4, PCI `1002:7551`,
  SMU 14.0.2, 32 GiB VRAM) and AMD Radeon RX 5600 OEM/5600 XT / 5700/5700 XT
  (Navi 10, PCI `1002:731f`, 8 GiB VRAM); run as ordinary user `mike`.
- Raw R9700 `gpu_metrics` v1.3 at idle: `throttle_status` `0x2` in 15 of 20
  250 ms samples, always with `indep_throttle_status` `0x1000000000`
  (TEMP_HOTSPOT only), hotspot 40 °C against a 110 °C limit.
- A genuine power-cap throttle under load was not reproduced live; the
  regression test covers the upstream-reported load pattern (`0x4002`,
  TEMP_HOTSPOT + PPT0 → `power`).
- Strix Halo (`1002:1586`) was not live-run for 0.2.1.
